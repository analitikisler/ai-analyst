# UX audit · AI Analyst, current build (23 Oct 2026)

Audited: `web/index.html`, `web/app.js`, `web/app.css`, `web/i18n.js`, run on the demo workspace at desktop and 375 px, dark and light. Each item names where it is and the fix the mockups in `design/mockups/` show.

| # | Problem | Where | Fix |
|---|---|---|---|
| 1 | Get started is three competing offers (demo, BigQuery, Cloud) and a list of models, with nothing to do in the app. The BigQuery path is a `.env` block to copy and a restart; the Anthropic key sits in the same block as the warehouse settings, so data and model look like one decision. | `paintStart`, `#start` | A three-step checklist with progress (Data, Model, First question). Each step is a choice made in the app, with "Test connection" for BigQuery and public data. The Cloud offer is one card beside the checklist, not a third tile competing with it. When all three are done the checklist disappears and the app opens on Ask. `start.html` |
| 2 | Settings are scattered: language and theme in the top bar, agent mode as a read-only line in the top bar, model options on Get started, the help email only in `.env`. There is no settings page. | `.topbar__end`, `paintStart`, README | One Settings page with six sections (Workspace, Model, Connect a chat app, Help and Cloud, Appearance, About). The top bar keeps the workspace, freshness and a settings button. `settings.html` |
| 3 | Ask opens on a seeded conversation shown as if the person had asked it, in the seed language (Turkish seed under an English UI, or the reverse). | `paintAsk` → `turnsToShow`, `seed.js` | Ask opens empty: a short greeting and four suggestions in the UI language. The worked example moves to the dashboard as a tile marked "Example". `ask-empty.html`, `dashboard.html` |
| 4 | Unused chrome around the composer: a "Try a question" chip row that repeats the follow-ups above it, an "Enter sends" hint, and the agent mode repeated three times on one screen (steps head, answer tag, composer foot). | `paintAsk`, `turnHTML`, `answerCard` | Composer alone, with the Ask button and Stop while running. Suggestions appear only on the empty state and as follow-ups under an answer. The model is named once, in Settings. `ask-empty.html`, `ask-answer.html` |
| 5 | Agent steps are always open as a raw mono log (tool names, ids such as `ans_1e3f2d9aff`), `white-space: nowrap`, so on phones the block scrolls sideways. | `.steps`, `stepsHTML` | Steps collapse to one line, "Checked 2 sources · 3 steps", a disclosure that opens to plain-words lines with the tool name as a tag. Lines wrap. While running, the last line says "working". `ask-answer.html` |
| 6 | The Cloud offer appears in four places: Get started, a note under Sources, a note under Alerts, and the "Email to find the cause" button on every failing check and answer. | `note_sources`, `note_alerts`, `helpLink` | One place to read about it (Settings › Help and Cloud, with the early access email) and one place to use it (the "Email to find the cause" action on an open check). Nothing on Sources or Alerts. `settings.html`, `checks.html` |
| 7 | Dashboard tiles are one shape: a figure, a fixed small chart, a close button. No chart type, size, period, comparison, rename or reorder, and only one dashboard. | `paintDashboard`, `.tiles` | A tile menu (chart type, size, period, compare, rename, move, remove), three tile sizes, a dashboard switcher with "New dashboard", and every option also phrased as something to ask the agent. `dashboard.html` |
| 8 | Four answer-sized Δ figures on the Checks page at once, each with a tally, a finding and three buttons, so the page reads as four answer cards and nothing is the answer. | `paintChecks`, `.row[data-cols="check"]` | A compact list (name, verdict, small tally, since-date) and one open check with the full tally, the one marked Δ, the by-device split, the linked finding and the actions. `checks.html` |
| 9 | Approvals are split: an "Alerts" section, a "1 ?" badge, a rail-foot line "1 needs approval", and an approval card inside the thread. Alerts and Activity are two sections for one log. | `paintAlerts`, `paintCounts`, `#rail-pending` | Alerts merge into Activity. The rail badge counts what waits on the person; Activity opens on a "Waiting" group with the decision inline; the same request is also inline in the thread where the agent stopped. `activity.html`, `ask-answer.html` |
| 10 | "Make an alert" creates the alert at once with no schedule, recipient or condition shown; the person does not know what was made. | `answerCard` → `create_alert` | A small dialog prefilled from the card (condition from the tally, daily 09:00, the person's email) with "Create" and "Cancel". The agent's proposals use the same shape as an inline approval. `ask-answer.html` |
| 11 | Phone layout: the top bar wraps to three rows (workspace, freshness, agent line plus language and theme), and the rail becomes a horizontally scrolling strip with no sign that it scrolls; Activity and Alerts are off screen. | `.topbar`, `.rail__nav` below 1024 | A bottom tab bar with Ask, Dashboard, Checks and More (a sheet with Metrics, Sources, Activity, Settings). The top bar is one row: workspace, freshness, settings. `mobile.html` |
| 12 | No way to try real data without editing files: no public data option, no in-app BigQuery connection, no test. The setup guide opens in a new tab and the app cannot tell whether the connection works. | `paintStart`, `docs/connecting-bigquery.md` | Step 1 of Get started offers demo, BigQuery public data (thelook_ecommerce with checks, GA4 sample with GA4 metrics only) and the company's own BigQuery, each with "Test connection" and the result in words (dataset found, dry run bytes, the cap). Credentials never pass through the browser; the form says which machine credentials it uses. `start.html` |
| 13 | The person's own AI plan has no honest route: the only choices are a key in `.env` or Cloud. The MCP server exists (`node src/cli.js mcp`) but the UI never mentions it. | README, `paintStart` | Model step and Settings › Model show four routes: Cloud, own API key (set / not set, never entered in the browser), a chat app over MCP (Claude Desktop, ChatGPT, Gemini, with the config snippet per app), and the built-in planner. `start.html`, `settings.html` |
| 14 | Answer card actions: "Pin to dashboard" is a primary button inside evidence, and "Pinned" is the same button toggled, so a card can carry the view's only primary. The orange mark sits on the answer's Δ and on the dashboard's `.metric` tile in the same view when the thread and dashboard share a page on phones. | `answerCard`, `paintDashboard` | No primary button inside a card; Pin opens a small menu (which dashboard, which size). The mark is on the open answer's Δ only; dashboard tiles carry `data-mark="none"` except the one headline tile per dashboard. `ask-answer.html`, `dashboard.html` |
| 15 | Copy says what the system is instead of what to do: "Agent: built-in planner" in the top bar, "built-in planner · no model call" as a tag on every answer, "steps_model: Claude · the same actions as the buttons". The one honest state the spec asked for, "not sure", is missing; a failed validation shows "not checked" with the unmatched numbers as ids. | `i18n.js`, `answerCard` | The model is named once in Settings. An answer that could not be grounded says "not sure" with the reason in words; one that has no source says "not checked · no source to compare". `ask-answer.html` |

Kept from the current build: the answer card's order (sentence, chart, tally, definition, SQL), the `.tally-bars` with the gap hatched, the status glyph and word, the findings block, the activity log with Undo, and the i18n number and date formatting.
